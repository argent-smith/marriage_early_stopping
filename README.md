# marriage_early_stopping

Идиоматичный OCaml-порт шуточного Python-класса `MarriageEarlyStopping`
— техника early stopping из машинного обучения, применённая к
отношениям. Учебный пример: как один и тот же сценарий выглядит в
императивном Python-классе с мутируемым `self` и в OCaml с
иммутабельными типами, разделением по SOLID и монадической композицией
там, где она реально упрощает код.

## Что показывает пример

- `marriage_early_stopping.py` — оригинал (транскрипция, 1:1): один
  класс, три метода, мутация `self`, без разделения на модули и без
  обработки ошибок.
- `marriage_early_stopping.ml` — порт: чистое ядро (`Tracker`) отдельно
  от вывода, события как данные (`Event`), а не текст, вывод через
  подключаемый `Logger` (ISP), два независимых представления одних и
  тех же событий (текстовое и sexp) без единой правки ядра (OCP).
  Ошибки — через `Or_error`, а не исключения; инфиксная монадическая
  композиция (`Or_error.(...)`, `Option.(...)`) — там, где есть
  реальная цепочка шагов, а не как самоцель.

Подробности архитектуры и разбор конкретных решений — в
[CLAUDE.md](CLAUDE.md).

## Сборка и запуск

Проект использует локальный opam switch (песочница `_opam/` в корне,
изолирована от прочих OCaml-проектов) и оформлен как opam-пакет —
[marriage_early_stopping.opam](marriage_early_stopping.opam)
генерируется dune из `dune-project` (сам файл не редактируется, в нём
только служебная пометка об этом):

```sh
opam switch create . 5.3.0 --yes
opam install . --deps-only --yes   # core, ppx_jane — по depends из .opam
dune build
dune exec ./marriage_early_stopping.exe
```
